## 1. ปัญหาของ palette เดิม (teal + amber)

teal/amber ของ v2 ดูดีในระดับภาพนิ่ง แต่พอเอามาใช้กับ product ที่แกนหลักเป็น step-through
visualizer มันมี **ความหมายชนกัน 2 จุด** ที่ทำให้อ่านยากขึ้นเรื่อยๆ ตอนบทเนื้อหาเยอะขึ้น

| สีเดิม | ถูกใช้แทนอะไรบ้างใน v2 | ปัญหา |
|---|---|---|
| amber `#F5B83D` | บรรทัด pseudocode ที่กำลังทำงาน, node เป้าหมาย, step ปัจจุบันใน timeline, badge `O(n)` worst case, ไอคอนจุดอ่อน, ป้าย LIVE | amber เป็นทั้ง **กำลังอยู่ตรงนี้** และ **นี่คือของแย่** พร้อมกัน ผู้เรียนต้องเดาเองทุกครั้งว่าอันไหนหมายถึงอะไร |
| teal `#2DD4BF` | brand, nav บทที่เปิดอยู่, เส้นทางที่เดินผ่าน, badge `O(log n)` ที่ดี, ตัวเลือกควิซที่ถูก, ปุ่ม play | teal เป็นทั้ง **โครงสร้าง/interactive** และ **ผลลัพธ์ที่ดี** ทำให้ nav กับ data มีน้ำหนักสายตาเท่ากัน |

พอ 2 role ทับกัน สิ่งที่เสียไปคือความสามารถกวาดตาแล้วรู้ทันทีว่าตอนนี้ algorithm อยู่ไหน
ซึ่งเป็นคุณค่าหลักของเว็บนี้เลย ไม่ใช่แค่เรื่องความสวย

### ทำไม palette นี้ตรงบรีฟ

- **dev-tool** ยังอยู่ครบ: พื้นดำอมน้ำเงิน + JetBrains Mono + accent น้ำเงิน คือภาษาเดียวกับ
  editor/terminal ที่คุ้นมือ ไม่ได้กลายเป็นเว็บเรียนออนไลน์สีพาสเทล
- **easy to digest**: amber เป็นสีอุ่นตัวเดียวในทั้งจอ ตาจะวิ่งไปหามันก่อนเสมอ พอใช้มันแทน
  จุดที่ algorithm อยู่ตอนนี้อย่างเดียว ผู้เรียนกวาดตาครั้งเดียวก็เจอว่าต้องดูตรงไหน
  เป็นการใช้สีทำงานแทนคำอธิบาย ตรงกับที่อยากได้ภาพมากกว่าตัวหนังสือ
- **การแยก accent (น้ำเงิน) ออกจาก success (เขียว)** ทำให้ตารางความซับซ้อนอ่านแยกจาก nav
  ได้จริง ต่างจาก v2 ที่ teal ทำทั้งสองอย่าง
- **warning เป็น rose ไม่ใช่เหลือง** ดูแปลกตอนแรก แต่ในเว็บนี้สิ่งเดียวที่ต้องการ warning คือ
  ต้นทุนของ algorithm กับกับดัก ซึ่งความหมายจริงคือแย่ ไม่ใช่ระวัง เลยเข้ากับโทนแดงมากกว่า
  และทำให้เหลืองว่างไว้ทำงานสำคัญกว่า
- ทุกสีผ่าน WCAG AA (4.5:1) บนพื้น `#0A0C10` ทั้งหมด: accent 6.9 / highlight 11.4 /
  success 11.4 / warning 7.7
- ไม่พึ่งสีเดี่ยวๆ ในการสื่อสาร: node ปัจจุบันมีทั้งสี + วงเรืองแสง pulse + ป้าย กำลังดู,
  บรรทัดโค้ด active มีทั้งสี + แถบซ้าย + พื้นหลัง เผื่อคนตาบอดสีน้ำเงิน/เหลือง

Typography ไม่เปลี่ยน คงของ v2 ทั้งหมด (JetBrains Mono + IBM Plex Sans + IBM Plex Sans Thai)
เพราะ Plex Sans Thai เป็นตัวเลือกที่ถูกอยู่แล้ว ไม่มีเหตุให้เปลี่ยน ไอคอนยังเป็น Lucide
ตาม `icons.md` โดยใน mockup ฝัง path ของ Lucide ตรงๆ พร้อมคอมเมนต์ชื่อไอคอนกำกับทุกตัว
เพื่อ map เข้า `lucide-react` ตอน build จริงได้ 1:1

## 3. Layout ที่เปลี่ยนจาก v2 และเหตุผล

### เปลี่ยนแกนของ visualizer จากคอลัมน์ขวา เป็นแถบบนกว้างเต็มจอ

นี่คือการเปลี่ยนหลักข้อเดียวของ v3

v2 วาง visualizer ไว้ในคอลัมน์ขวา 460px แล้วเรียงทรี narration pseudocode ปุ่มควบคุม
ซ้อนกันลงมาในแนวตั้ง ปัญหาคือ

1. **ให้พื้นที่ผิดแกน** ทรี, array, hash bucket, DP table โตทางกว้าง ส่วนย่อหน้าอธิบายโตทางสูง
   v2 ให้ไดอะแกรม 360px กว้าง แล้วให้ตัวหนังสือ 680px ซึ่งกลับทางกันพอดี บท DP กับ hash table
   จะยัดไม่ลงตั้งแต่ยังไม่เริ่มเขียน
2. **ระยะสายตาระหว่างไดอะแกรมกับ pseudocode ห่างเกิน** ของสองอย่างนี้ต้องอ่านพร้อมกัน แต่ v2
   วางห่างกันประมาณ 300px ในแนวตั้ง ต้องกวาดตาขึ้นลงทุกครั้งที่กดถัดไป ซึ่งกินความสนใจของ
   working memory ไปเปล่าๆ
3. **พอจอแคบกว่า lg คอลัมน์ขวาตกลงไปใต้เนื้อหาทั้งก้อน** ของที่เป็นหัวใจของเว็บหลุดจอไปเลย

v3 ทำแบบนี้แทน

- แถบ visualizer เป็น `sticky top-[56px]` กว้างเต็มความกว้างเนื้อหา ไดอะแกรมอยู่ซ้าย
  (`1fr`) pseudocode อยู่ขวา (`412px`) **วางข้างกันในระดับสายตาเดียวกัน** ระยะกวาดตาเหลือ
  แนวนอนสั้นๆ
- narration เป็นแถบเดียวพาดใต้ทั้งสองช่อง ไม่แทรกกลางทำให้ของสองอย่างแยกกัน
- เนื้อหาเลื่อนอยู่ข้างล่างในคอลัมน์เดียว `max-w-[780px]` ได้ measure ที่อ่านสบายกว่า v2
  และยังเห็น visualizer ค้างอยู่ตลอด (ได้ประโยชน์เดิมของ sticky ขวา โดยไม่แลกความกว้างการอ่าน)
- มีปุ่มย่อแถบเหลือแค่ header สูง 46px สำหรับตอนอยากอ่านเนื้อหายาวๆ (แก้ข้อเสียเดียวของ
  sticky ด้านบน คือกินความสูงบนโน้ตบุ๊ก)

### เปลี่ยนอื่นๆ

| จุด | v2 | v3 | เหตุผล |
|---|---|---|---|
| step timeline | แถบเปล่า 7 อัน | chip มีป้ายชื่อขั้น (`1 root`, `2 37 > 30`, `4 37 < 42` …) กดกระโดดได้ | แถบเปล่าบอกได้แค่ว่าเหลืออีกไกลแค่ไหน อ่านทบทวนย้อนไม่ได้ chip ที่มีป้ายกลายเป็นสรุปทั้ง algorithm ในบรรทัดเดียว และกดย้อนกลับไปดูขั้นที่ไม่เข้าใจได้ตรงๆ |
| ตัว visualizer | ภาพนิ่ง frozen ที่ step 4 | เดินได้จริงทั้ง 7 ขั้น ผูก node + บรรทัดโค้ด + narration + comparison pill พร้อมกัน มี play/pause และคีย์ `←` `→` `space` `R` | ต้องกดเล่นจริงถึงจะตัดสินได้ว่า sync ระหว่างโค้ดกับภาพใช้งานได้จริงไหม และเป็นโครงที่ย้ายไป React ได้ตรงๆ (state เดียวคือ index ของ step) |
| rail ซ้าย | เลขบทเปล่า 01-08 | ไอคอน Lucide ต่อบท ตาม `icons.md` + เลข + วงแหวนความคืบหน้า | ไอคอนเลือกไว้แล้วใน `icons.md` แต่ v2 ไม่ได้ใช้ เลขเปล่ากวาดตาหาบทไม่ได้ ไอคอนจำรูปได้เร็วกว่าจำเลข |

| legend | ไม่มี | แถวเล็กใต้ไดอะแกรม บอกความหมาย 4 สถานะ | ทำให้กฎ 1 สี 1 ความหมาย ถูกประกาศออกมาตรงๆ ไม่ต้องให้ผู้เรียนเดา |
| flowchart | ไม่มี | ผังตัดสินใจต่อ 1 node ในส่วน Concept | บรีฟขอ flowchart และมันแยกหน้าที่กันชัด: ผังคือกฎ แถบบนคือการทำงานจริงทีละขั้น |
| ตาราง complexity | 3 แถว | เพิ่มแถว Space + คอลัมน์ Growth เป็นแท่งเล็ก + เชิงอรรถอธิบาย log n เป็นภาษาคน | เปลี่ยนตารางจากตัวหนังสือล้วนเป็นของที่กวาดตาเทียบกันได้ |
| ควิซ | 1 ข้อ แสดงคำตอบค้างไว้ | 2 ข้อ กดตอบได้จริง เฉลย + คำอธิบาย 1 บรรทัดหลังตอบ | บรีฟบอก 2-3 ข้อ และการเฉลยพร้อมเหตุผลสำคัญกว่าการบอกแค่ถูกหรือผิด |
| พื้นหลัง | dot grid ทั้งหน้า | dot grid แค่ rail กับแถบ visualizer | เนื้อหาที่ต้องอ่านยาวๆ ควรนิ่ง ปล่อย texture ไว้ในโซนเครื่องมือ ช่วยแยกโซนอ่าน ออกจากโซนเล่นด้วย |

## 4. สิ่งที่ต้องแก้ใน tokens.json ถ้ารับ palette นี้

ยังไม่ได้แก้ให้ ตามที่สั่ง ด้านล่างคือรายการที่ต้องทำ โครงสร้าง 3 ชั้นเดิมใช้ได้หมด
เปลี่ยนแค่ค่าใน `primitive` กับปลายทางของ alias บางตัวใน `semantic`

### primitive.color

1. `ink` เปลี่ยนค่า (ยังใช้ชื่อเดิมได้)
   - `950` `#0b0c10` → `#0A0C10`
   - `900` `#111318` → `#13171E`
   - `800` `#161920` → `#1A1F28`
   - `700` `#1d212a` → `#222834`
   - `600` `#2a2f3a` → `#2E3541`
   - **เพิ่ม** `ink.rail` = `#0D1016` (พื้น rail) และย้าย `code-surface` `#0d0f13` → `#0B0E13`
2. `text.primary` `#e9ebf0` → `#E7EAF1`, `text.muted` `#8b93a3` → `#929AAB`,
   `text.faint` `#5b6172` → `#646C7E`
3. **ลบ ramp `teal` ทั้งก้อน** แล้วเพิ่ม ramp ใหม่ 4 ตัว
   - `blue`: `300 #C3D3FF`, `400 #9CBBFF`, `500 #6E9BFF`, `600 #4E7DE8`,
     `soft rgba(110,155,255,0.13)`
   - `amber`: แก้ค่าเดิมเป็น `300 #FFD79A`, `400 #FFBE5C`, `500 #E8A23C`,
     `soft rgba(255,190,92,0.13)`
   - `green`: `300 #8BF2C6`, `400 #46E3A0`, `500 #26C080`, `soft rgba(70,227,160,0.13)`
   - `rose`: แทน ramp `red` เดิม `400 #FF7D8F`, `500 #F2555F`,
     `soft rgba(255,125,143,0.13)`
4. `black` `#04201c` → `#06101F` แล้วเปลี่ยนชื่อเป็น `on-accent` (เพราะมันคือสีตัวอักษร
   บนพื้น accent ไม่ใช่สีดำทั่วไป และมันต้องเปลี่ยนตาม accent)

### semantic.color

5. `accent` → `{primitive.color.blue.500}`, `accent-hover` → `blue.400`,
   `accent-soft` → `blue.soft`, `accent-foreground` → `on-accent`
6. `highlight` → `{primitive.color.amber.400}`, `highlight-soft` → `amber.soft`
   **และเพิ่มคอมเมนต์กำกับว่าสงวนไว้ให้สถานะกำลังอยู่ตรงนี้เท่านั้น**
7. **เพิ่ม** `success` → `green.400`, `success-soft` → `green.soft`
   (ตอนนี้ยังไม่มี success ใน semantic เลย ทั้งที่ complexity badge กับควิซต้องใช้)
8. `warning` → `rose.400`, `warning-soft` → `rose.soft` และให้ `danger` → `rose.500`

### component

9. `complexity-badge.good-bg/good-fg` เปลี่ยนจาก `accent-soft/accent`
   → `success-soft/success` (ตอนนี้ชี้ไป accent อยู่ ซึ่งคือต้นตอของปัญหาข้อ 1)
   และ `warn-bg/warn-fg` จาก `highlight-soft/highlight` → `warning-soft/warning`
10. `quiz-option.correct-bg/correct-border` จาก `accent-soft/accent`
    → `success-soft/success` และ **เพิ่ม** `wrong-bg/wrong-border` ชี้ไป `warning-soft/warning`
